Opening

If your website goes down, how do you find out? Too often, it's a customer who tells you.

This is SitePulse, a website uptime monitor I'm presenting today. It checks your sites every 60 seconds, records every result, and emails you when a site goes down and again when it comes back.

What it does

Show the Overview page

This is the dashboard. At the top you can see how many sites are up, any open incidents, uptime, and average response time.

One failed check doesn't mean a site is down, because that could just be a network blip. So SitePulse only marks a site down after 3 failures in a row, and up again after 2 successes. That avoids false alarms.

Uptime is also reported honestly. This tile says "Not enough data" because the project hasn't been monitoring for long. It would be easy to show 100%, but that wouldn't be true yet.

How it's built

It's built on the MERN stack: MongoDB, Express, React and Node.

Three design choices are worth mentioning. First, several workers can run safely: each one claims a site before checking it, so two workers never check the same site at once.

Second, alerts survive crashes: they're saved to the database before sending, so a restart doesn't lose them, and a failed send is retried automatically.

Third, mail problems are visible: if an alert can't be sent, the dashboard says so, so you aren't left assuming everything is fine.
